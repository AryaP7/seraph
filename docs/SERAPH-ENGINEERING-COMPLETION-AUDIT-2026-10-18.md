# SERAPH — engineering completion audit

Audit date: 18 October 2026. Checkout: `C:\Users\Arlop\Downloads\SERAPH VARYA\SERAPH Varya`.

## Verdict

**SERAPH is a substantial working prototype, but development is not finished even if predictive performance and model mathematics are deliberately set aside.** The largest unfinished pieces are the actual live producers, reliable restart/state handling, a single live application path, authenticated persistent role workflows, news processing correctness, and install/operate/recover tooling.

The main console can display saved research outputs and real news. That does not mean the normal launch path can ingest today's market, compute all available pillar outputs, persist a fresh decision, update the original console, and deliver a user's alert. That complete path is still missing.

This register contains **55 engineering work packages**. They are not 55 newly discovered bugs, equally sized tasks, or a percentage denominator. Some consolidate earlier findings, some are missing integrations, and some are acceptance work for code already written. Cross-references preserve the older ticket identities.

## Boundary: finish development now, science later

Engineering completion can be declared without demonstrating crisis prediction, provided the delivered product explicitly remains an experimental risk/research system. Keep Hawkes, RMT and Hamilton and their existing eligibility decisions. An excluded model can be implemented, executed diagnostically and correctly withheld; it need not be falsely promoted to satisfy a software checklist.

**Do now:** data validation; clocks and availability; complete input/output contracts; real producer adapters; persistence; recoverability; role workflows; evidence rendering; correct benchmark calculations; versioned model/configuration loading; operational monitoring; installation; and end-to-end acceptance.

**Defer to science:** choosing better mathematical models, proving advance-warning skill, calibrating risk/alert thresholds, economic effect sizes, causal attribution, monetary loss models, fitting a new policy-to-regime mapping, independent interpretation accuracy, and prospective usefulness. Do not weaken these gates or replace unknown values with plausible numbers. News interpretation contradictions and incorrect evaluation denominators are software defects, even though interpretation quality also requires empirical validation.

**External input is a third category:** broker authorization, identity-provider configuration, source access/rights, missing historical datasets, and independent reviewers. Code can be ready while these remain unavailable, but an unexercised real-service integration is not verified delivery.

## Priority and status vocabulary

**P0:** materially incorrect data/identity, broken essential runtime path, or broken distribution. Fix before relying on the affected function. **P1:** required to finish the intended product. **P2:** expanded product/deployment capability after the core path; still unfinished if included in the promised release.

**Defect** means a current mechanism is wrong. **Integration gap** means useful code exists but the normal caller does not use it. **Partial** means part is implemented. **Verification gap** means acceptance is not established. For each row, the last column is the evidence needed to mark it done. Dependencies identify the main prerequisite, not every imported module.

## What “engineering complete” should mean for this project

- The documented launcher brings up a coherent application and all required workers, with a useful empty state and explicit missing configuration.
- Real authorized inputs reach actual producers and the main console; diagnostic/ineligible/missing outputs are withheld honestly.
- Every visible promised operation works through normal UI/API paths, persists where expected and respects server-side identity in shared mode.
- Inputs, decisions, evidence, scenarios and corrections survive retries/crashes/restarts without losing history or accepting conflicting identities.
- Current, stale, replay, scenario, estimate, unavailable and fabricated content remain distinguishable at the datum and screen level.
- A separately installed build includes all assets, data and migrations and can be restored from an exercised backup.
- Engineering acceptance and known limitations are recorded against exact versions. Science gates are still shown as unpassed where appropriate.

**Do not postpone time semantics, input integrity, news contradictions or evaluator correctness under “fix the math later.”** Those defects would contaminate the evidence used to fix the science. Conversely, do not hold ordinary engineering integration hostage to achieving AUC, lead-time, calibration or economic-impact targets. A complete experimental platform with honest unvalidated outputs is a legitimate engineering milestone.
